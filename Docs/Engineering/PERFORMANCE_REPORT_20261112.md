| 指标 | 实测 |

## 3. 10 GB 大文件（通过，稀疏实测）

命令：`swift run V3Acceptance perf <workRoot> large 10737418240 0.25`

| 指标 | 实测 |
|---|---|
| 逻辑大小 | 10,737,418,240 bytes |
| 源文件物理大小 | 9,453,961,216 bytes（0.25 稀疏比例） |
| 首次备份 | 357.42 s |
| 增量备份 | 290.22 s |
| 首次上传 | 1,901,425,797 bytes / 2,056 objects |
| 增量上传 | 1,026,542 bytes / 1 object |
| 云端字节 | 1,903,887,143 |
| 峰值 RSS | 2,056,126,464 bytes（约 1.91 GiB） |
| Spool 结束后 | 0 |
| committed | true |

结论：

- 10 GB 逻辑文件采用流式分块；增量只上传约 1 MB，去重有效。
- 峰值 RSS 约 2 GB，说明没有把 10 GB 文件整体载入内存，但内存占用仍偏高，需继续优化。
- 本次是 0.25 物理比例的稀疏数据，不是全随机 10 GB；报告明确标注。

原始日志：`Docs/Engineering/TestArtifacts/taskbook-10gb-benchmark-20261113.log`
