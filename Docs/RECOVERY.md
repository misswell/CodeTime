# CodeTime 恢复指南

## 1. 四种恢复方式

| 模式 | 适用场景 | 写入位置 | 保护措施 |
| --- | --- | --- | --- |
| 仅预览 | 查看历史内容 | 不写磁盘 | — |
| 恢复副本 | 日常找回，推荐默认 | 用户选择的新位置 | 目标已存在则拒绝覆盖 |
| 覆盖原文件 | 确认要用历史版本替换当前文件 | 项目内单个文件 | 先复制到 `recovery/<时间戳>/`，失败则中止；二次确认 |
| 恢复整个项目 | 换机、重构、灾难恢复 | 用户选择的空目录 | 目录非空则拒绝 |

**CodeTime 绝不允许默认覆盖当前开发代码。** 覆盖模式只对单文件开放，且必须先完成
“当前文件保护副本”。

## 2. 从时间机器恢复单个文件

1. 概览 → 打开项目 → 时间机器。
2. 在右栏选择时间点；左侧浏览目录，单击文件查看内容。
3. 预览窗格右上角“恢复此版本”，或项目工具栏“恢复”菜单。
4. 选择“恢复副本”，指定保存位置。
5. 若确需覆盖项目文件：选择“覆盖原文件”，阅读保护说明并勾选确认。

恢复记录会出现在“恢复记录”页面。

## 3. 恢复整个项目

1. 时间机器右上角“恢复” → “恢复整个项目…”。
2. 选择一个新的空目录（可用“新建文件夹”）。
3. CodeTime 通过 Kopia 把快照展开到该目录，包括 `.git`（若已备份）。
4. 不会覆盖任何已有文件；目录非空会直接报错。

恢复完成后，可以自行把目录移动到目标位置，或在 CodeTime 中作为新项目添加。

## 4. 全新 Mac 从 iCloud 恢复

前提：

- 旧 Mac 已成功发布至少一个云端版本（设置 → 云端中能看到版本与容量）。
- 拥有离线保存的恢复密钥。
- 新 Mac 已登录同一个 iCloud 账户，且 iCloud Drive 中可见 `CodeTime/`。

步骤：

1. 安装并首次启动 CodeTime（不要在旧数据上操作）。
2. 设置 → 云端 → “从云端恢复…”。
3. 选择 iCloud Drive 中的 `CodeTime` 文件夹。
4. 输入恢复密钥（`CT1-…`）。
5. CodeTime 将：
   - 枚举所有设备/仓库的恢复凭据，逐候选校验密钥指纹与解密结果；
   - 列出可恢复候选及阻塞原因（密钥不匹配、版本不可读等），一个候选失败不会中止搜索；
   - 选择目标 Generation 后写入 staging 仓库，逐对象下载并校验 SHA-256；
   - 已校验对象在中断后跳过，应用重启可继续（断点恢复）；
   - 全部完成后校验仓库与快照，通过后才切换到正式仓库位置；
   - 写入新 Mac 的 Keychain，并用 Kopia 连接仓库、列出历史项目路径。
6. 对每个仍存在的项目路径，点击添加；随后即可在时间机器中浏览历史快照。

注意：

- 云端恢复一次恢复一个设备目录的仓库；多设备历史不会自动合并，但会显示所有候选供选择。
- 恢复失败不会修改现有正式仓库；staging 保留以便重试。
- 恢复后在“诊断”中确认仓库连接与校验状态。
- 恢复只会写入新 Mac 的 `Application Support/CodeTime`，不会覆盖已有本地备份；
  若本机已有快照，应用会拒绝执行云端恢复。

## 5. 恢复等级

| 等级 | 含义 |
| --- | --- |
| `cloudIntegrity` | 校验云端对象存在且哈希一致 |
| `localRestore` | 在本机执行实际恢复并验证内容 |
| `crossDeviceRestore` | 在另一台 Mac 上从云端重建仓库并读取快照 |

只有 `crossDeviceRestore` 才能标注“异机恢复验证通过”。本地抽样恢复不等于灾难恢复。

## 6. 手动/离线恢复

当应用无法启动但仍有本地仓库时：

1. 本地仓库位于
   `~/Library/Application Support/CodeTime/repositories/<id>/repo`。
2. Kopia 配置位于同目录的 `kopia.config`；仓库密码在 Keychain（服务
   `com.codetime.app`，账户 `repository-password`）。
3. 应用内置 Kopia：
   `CodeTime.app/Contents/Resources/Kopia/kopia`。
4. 可使用该二进制执行只读检查：

```bash
K=.../Contents/Resources/Kopia/kopia
CFG=~/Library/Application\ Support/CodeTime/repositories/<id>/kopia.config
KOPIA_PASSWORD='<from keychain>' "$K" --config-file="$CFG" snapshot list --json --all
KOPIA_PASSWORD='<from keychain>' "$K" --config-file="$CFG" snapshot restore <id> /tmp/restore
```

云端离线恢复需要按 `Docs/CLOUD_FORMAT.md` 重组仓库；CodeTime 应用内已自动化此流程。

## 7. 恢复密钥丢失

- 恢复密钥只存在于：
  1. 用户离线保存的位置；
  2. 当前 Mac 的 Keychain。
- 若两者都不可用，Kopia 仓库密码与云端清单都无法解密，**备份内容不可恢复**。
- CodeTime 没有后门、没有服务端密钥托管，也不会向任何服务器上传恢复密钥。
- 建议：打印一份或存入独立密码管理器，不要只保存在同一台 Mac 上。

## 8. 恢复失败排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| “云端对象缺失” | iCloud 尚未下载完 / 对象被手动删除 | 等待同步完成后重试；用“校验云端”定位 |
| “清单损坏/密钥不匹配” | 恢复密钥错误或清单被篡改 | 核对恢复密钥；不要删除旧清单 |
| “目标已存在” | 恢复目标非空 | 选择新目录；覆盖模式仅支持单文件 |
| “仓库密码错误” | Keychain 条目被替换/删除 | 使用恢复密钥重新执行云端恢复 |
| 覆盖保护失败 | 磁盘满 / 权限不足 | 释放空间或修复权限，操作已中止 |
